# 需求文档 - 前端功能差异分析与补齐

## 介绍

通过对比 Gekko-die (旧版) 与 Gekko-reborn (新版) 前端项目，发现新版在数据导入、回测配置深度、实盘交易管理以及设置管理等方面存在显著功能缺失。本文档旨在定义需要补齐的核心功能需求，以确保新版 Gekko 具备完整的交易平台能力。

## 需求

### 需求 1 - 市场数据导入 (Data Importer)

- **用户故事**:
  作为一名交易者，我希望能够从交易所导入历史市场数据 (Candles)，以便使用真实历史数据来回测我的策略。

#### 验收标准

1. **While** 在"市场数据"页面，**When** 用户点击"导入数据"按钮，**the** 系统应当显示导入配置表单。
2. **When** 用户配置导入任务时，**the** 系统应当允许用户选择交易所 (Exchange)、资产 (Asset)、货币 (Currency) 和时间范围 (Date Range)。
3. **When** 导入任务开始后，**the** 系统应当显示导入进度条和当前状态。
4. **When** 导入完成后，**the** 系统应当将新数据集显示在可用数据集列表中。

### 需求 2 - 高级回测配置 (Advanced Backtest Config)

- **用户故事**:
  作为一名策略师，我希望能够选择特定的历史数据集，并调整策略参数进行回测，以便精确评估策略在不同市场环境下的表现。

#### 验收标准

1. **While** 在"策略"页面或独立"回测"页面，**When** 用户选择"运行回测"，**the** 系统应当允许用户选择已导入的数据集（而非仅使用模拟数据）。
2. **When** 用户配置回测时，**the** 系统应当允许用户修改当前策略的参数 (Parameters)。
3. **When** 回测执行时，**the** 系统应当调用后端回测引擎并等待结果。

### 需求 3 - 回测结果可视化 (Backtest Results)

- **用户故事**:
  作为一名策略师，我希望看到详细的回测结果，包括收益曲线、交易列表和性能指标，以便深入分析策略优劣。

#### 验收标准

1. **When** 回测完成后，**the** 系统应当展示收益曲线图 (Equity Curve)，并在图表上标记买入/卖出点。
2. **When** 查看结果详情时，**the** 系统应当展示关键性能指标 (Sharpe Ratio, Max Drawdown, Profit, Win Rate)。
3. **When** 查看结果详情时，**the** 系统应当展示完整的交易记录列表 (Roundtrips)。

### 需求 4 - 实盘/模拟交易管理 (Live Trading Manager)

- **用户故事**:
  作为一名交易者，我希望能够配置并启动实盘或模拟交易机器人，以便自动执行我的策略。

#### 验收标准

1. **When** 用户进入"交易机器人"或"控制台"页面，**the** 系统应当允许创建新的交易实例。
2. **When** 创建实例时，**the** 系统应当允许选择 交易模式 (Paper Trader / Live Trader)。
3. **When** 处于 Live Trader 模式，**the** 系统应当要求用户选择有效的 API Key。
4. **When** 实例运行时，**the** 系统应当实时展示其日志、当前持仓和盈亏状况。

### 需求 5 - 设置与 API 密钥管理 (Settings & API Keys)

- **用户故事**:
  作为一名用户，我希望能够安全地管理交易所 API 密钥，以便系统能够连接交易所进行交易或数据获取。

#### 验收标准

1. **While** 在"设置"页面，**When** 用户选择"API 密钥管理"，**the** 系统应当列出已保存的密钥（脱敏显示）。
2. **When** 用户添加新密钥时，**the** 系统应当加密存储 Key 和 Secret。
3. **When** 用户删除密钥时，**the** 系统应当从数据库中物理删除相关记录。
