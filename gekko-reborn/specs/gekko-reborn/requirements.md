# 需求文档 - Gekko Reborn

## 介绍

本项目旨在对经典的 Gekko 量化交易机器人进行现代化重构。原项目已停止维护且基于过时的技术栈（Node.js 8, Koa 1），存在性能瓶颈与安全隐患。
Gekko Reborn 将保留原项目的优秀架构设计（流式处理、插件化、多进程隔离），并采用现代技术栈（TypeScript, NestJS, RxJS）进行重写，以提供更高效、安全、可扩展的量化交易平台。

## 核心需求

### 需求 1 - 市场数据接入 (Market Data)

- **用户故事**: 作为策略开发者，我希望系统能接入主流交易所（Binance, OKX 等）的实时行情和历史数据，以便策略进行分析。
- **验收标准**:
  1.  提供统一的 `ExchangeAdapter` 接口，屏蔽不同交易所 API 差异。
  2.  支持 REST API 获取历史 K 线数据。
  3.  支持 WebSocket 订阅实时 Ticker 和 Trade 数据。
  4.  实现 `MarketStream`，以 RxJS Observable 形式向下游推送标准化数据。

### 需求 2 - 策略引擎 (Strategy Engine)

- **用户故事**: 作为策略开发者，我希望能够使用 TypeScript 编写交易策略，利用内置的技术指标库进行信号生成。
- **验收标准**:
  1.  提供 `BaseStrategy` 基类，包含 `onCandle`, `onTick` 等生命周期钩子。
  2.  集成常用技术指标库（如 TA-Lib 或 Tulip Indicators 的 TS 版本）。
  3.  策略应能访问历史窗口数据（Warmup period）。
  4.  支持配置参数动态注入策略。

### 需求 3 - 回测系统 (Backtesting)

- **用户故事**: 在实盘投入资金前，我希望用历史数据验证策略的表现，并获得详细的性能报告。
- **验收标准**:
  1.  支持指定时间范围、交易对、K 线周期进行回测。
  2.  模拟撮合引擎应考虑手续费、滑点（Slippage）。
  3.  生成回测报告，包含：总收益率、最大回撤、夏普比率、胜率等关键指标。
  4.  回测过程应在独立进程或 Worker 中运行，不阻塞主线程。

### 需求 4 - 实盘与模拟交易 (Live & Paper Trading)

- **用户故事**: 我希望系统能根据策略信号自动下单，并支持“模拟盘”模式以无风险测试实盘逻辑。
- **验收标准**:
  1.  **模拟盘 (Paper Trader)**: 实时接收市场数据，但在本地模拟账户资金变动，不发送真实订单。
  2.  **实盘 (Live Trader)**: 通过交易所 API 发送真实买卖订单。
  3.  支持订单生命周期管理（创建、部分成交、完全成交、取消）。
  4.  具备基本的风控机制（如最大持仓限制、止损保护）。

### 需求 5 - 插件化架构 (Plugin Architecture)

- **用户故事**: 我希望系统功能（如存储、通知）是可插拔的，以便根据需要启用或扩展。
- **验收标准**:
  1.  **数据存储插件**: 支持 SQLite, PostgreSQL, MongoDB 等多种后端，用于存储历史 K 线和交易记录。
  2.  **通知插件**: 支持 Telegram, Email, Discord 等渠道发送交易信号和异常报警。
  3.  插件应通过配置文件启用/禁用，无需修改核心代码。

### 需求 6 - 现代 Web UI

- **用户故事**: 我希望通过浏览器管理机器人，查看实时图表和回测结果。
- **验收标准**:
  1.  提供 Dashboard 查看当前运行的机器人状态。
  2.  可视化配置界面，用于创建新的回测或实盘任务。
  3.  基于 TradingView Lightweight Charts 或类似库展示交互式 K 线图和买卖点。
  4.  API 接口需鉴权，API Key 等敏感信息需加密存储。

## 非功能性需求

1.  **性能**: 核心数据流使用 RxJS 处理，确保高吞吐量和低延迟。
2.  **安全**: 所有交易所 API Key 必须加密存储（AES-256）；Web 访问需 JWT 认证。
3.  **可维护性**: 全栈 TypeScript，后端使用 NestJS 框架，前端使用 React/Vue (建议 React + Ant Design 或 Next.js)。
4.  **部署**: 提供 Docker Compose 一键部署方案。
